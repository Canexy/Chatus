# Instrucciones para Despliegue Seguro del Proyecto

## Carpetas y Archivos para Subir

### 1. Render (Backend)
Sube la carpeta `backend/` a Render. Esta carpeta contiene el código del servidor Node.js y la lógica de Socket.IO.

- **No subir**:
  - `.env`: Este archivo contiene información sensible como claves API y configuraciones privadas. No debe subirse a GitHub ni a Render directamente.
  - `node_modules/`: No es necesario subir esta carpeta, ya que Render instalará las dependencias automáticamente usando `package.json`.

- **Acciones necesarias**:
  - Crea variables de entorno en Render para las claves y configuraciones que están en `.env`.

### 2. Vercel o Netlify (Frontend)
Sube la carpeta `frontend/` a Vercel o Netlify. Estas plataformas son ideales para proyectos React y tienen planes gratuitos.

- **No subir**:
  - `.env.local`: Este archivo contiene información sensible y no debe subirse.
  - `node_modules/`: No es necesario subir esta carpeta, ya que Vercel/Netlify instalarán las dependencias automáticamente usando `package.json`.

- **Acciones necesarias**:
  - Configura las variables de entorno en Vercel o Netlify para las claves y configuraciones que están en `.env.local`.

### 3. Supabase
No necesitas subir carpetas directamente a Supabase, ya que este servicio gestiona la base de datos y las funciones RPC desde su consola web.

- **Acciones necesarias**:
  - Asegúrate de que las migraciones y configuraciones estén aplicadas en tu instancia de Supabase (ver `info_supabase.txt` como referencia orientativa).
  - Configura las políticas de seguridad (RLS) y las funciones RPC desde la consola de Supabase.

## Archivos Sensibles y Buenas Prácticas

### Archivos sensibles identificados:
- `backend/.env`
- `frontend/.env.local`

### Qué hacer con ellos:
1. **No subirlos a GitHub**:
   - Asegúrate de que estos archivos estén listados en `.gitignore` para evitar que se suban accidentalmente.
2. **Sustituirlos de forma segura**:
   - Usa variables de entorno en los servicios de despliegue (Render, Vercel, Netlify).
   - Documenta las claves necesarias y sus valores en un archivo de instrucciones (sin incluir las claves reales).

---

## Pasos para el Despliegue

### 1. Preparar el Backend (Render):
- Sube la carpeta `backend/` a un repositorio GitHub privado o directamente a Render.
- Configura las variables de entorno en Render basándote en el archivo `.env`.

### 2. Preparar el Frontend (Vercel/Netlify):
- Sube la carpeta `frontend/` a un repositorio GitHub público o directamente a Vercel/Netlify.
- Configura las variables de entorno en Vercel/Netlify basándote en el archivo `.env.local`.

### 3. Configurar Supabase:
- Aplica las migraciones y configuraciones desde la consola de Supabase (ver `info_supabase.txt` como referencia).
- Verifica las políticas RLS y las funciones RPC.

### 4. Probar el Proyecto:
- Asegúrate de que el frontend puede comunicarse con el backend y Supabase.
- Prueba las funciones críticas como login, chat en tiempo real y administración.

### 5. Publicar en GitHub:
- Sube solo los archivos necesarios, excluyendo los sensibles.
- Usa un archivo `.gitignore` para evitar subir `.env`, `.env.local` y `node_modules/`.
